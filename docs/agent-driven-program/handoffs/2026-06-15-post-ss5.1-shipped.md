## 4. Durable design decisions / lessons from SS-5.1 (apply next session) ⭐

- **The Codex companion runs a BARE prompt-file — it does NOT load Claude agent/skill system prompts.** Any return/behavioral contract a Claude subagent gets implicitly from its `agents/*.md` MUST be embedded verbatim in the Codex prompt-file. Never reference "your agent contract" / "your instructions" on the Codex path. Add a test that the dispatched prompt-file carries the contract. (Memory: `feedback_codex_companion_no_auto_load_contract`; SS-5 spec §3.8 had this — it recurs.)
- **The synthesizer backend is *simpler* than the implementer.** No worktree, no no-commit verify, no gaps-mode — synthesis writes the artifact in place and returns `complete|failed`. Reuse for any future "Codex does derivation" surface (e.g., #39).
- **Prompt-source-agnostic adapter.** The codex dispatch spine doesn't care which assembler built the prompt — keep it that way; branch only the dispatch, never fork the prompt or the validators.
- **`tests/fixtures/` is gitignored in scaffold-onboard** (generated-at-runtime, unlike scaffold-dev). Committed test doubles go elsewhere (`tests/codex-shim/`). (Memory: `reference_codex_dual_publish_test_location`.)
- **For a Codex async backend, validate only on `term == completed` AND `mode == complete`** — synthesize a `mode:failed` for any other terminal status, then route to the same-backend retry-once → hard-fail. Don't call `result` on a failed/stalled job.
- **The bot-review round is non-negotiable for cross-tool work** even after a clean holistic review — the no-auto-load-contract class is exactly what an inline build + same-context review miss but a fresh-frame Codex review catches. (Memory: `bot_review_convergence_judgment`.)
