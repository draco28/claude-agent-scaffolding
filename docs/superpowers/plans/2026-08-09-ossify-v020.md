## Global Constraints

- **`bin/oss` runs `set -euo pipefail`; the test harness does not.** Tests source `lib/*.sh` directly, so a strict-mode bug can ship green. Every lib change needs a dispatcher-path assertion (`./ossify/bin/oss <verb> …`), not only a sourced-function assertion.
- **Never reason about shell semantics under zsh.** The interactive shell here is zsh, which runs the last pipeline element in the parent shell and hides a whole bug class. `run-all.sh` forces `bash`; so must every reproduction you write.
- **`plan-spine/SKILL.md` and `start/SKILL.md` are at exactly 499/500 lines.** Any edit adding a line to either needs a trim in the same commit. `check 6` in `tests/test-skill-bash-blocks.sh` enforces the 500-line cap.
- **The entry-skill description budget is 3,121 characters total** (C1's trimmed figure). It is **currently 3,135 — already 14 over** — and **no test enforces it**. Task 1 fixes both.
- **Do NOT register ossify in `.claude-plugin/marketplace.json`** and do NOT add a `.codex-plugin` manifest. That is Plan D's ship gate; early registration breaks `tests/test-codex-dual-publish.sh`, which needs both together.
- **Do NOT `git clean -fdx`.** It destroys `.superpowers/sdd/progress.md`, which is gitignored and is this series' recovery map.
- **Do NOT touch `README.md`** — it carries the user's own uncommitted edit.
- **Do NOT `git add -A`** — always explicit paths.
- **No squash merges.** Standing policy as of 2026-08-09: merge commits (or rebase-merge), never squash — the per-commit history is needed to validate and review the work later. `--no-ff` on the merge so the branch's shape survives. All three merge methods are enabled on the repo, so this is discipline, not configuration.
- **Tag after the merge, not before.** Under the new no-squash policy the branch commits *are* ancestors of `main`, so a branch-tip tag is no longer automatically orphaned — the specific trap that hit `ossify-v0.1.0` (squashed into `a5d61f1`, leaving the tagged `bbd785c` unreachable and 133 insertions behind) is gone. Tag after the merge anyway, for a different reason: **the tag must point at what actually shipped**, including any fixes added during the review round. Verify reachability with a concrete observable either way.
- **architect-critic, the only supported form:** `export ARCHITECT_CRITIC_ARGS="--spec \"<abs path>\" --close"` then a bare `Skill(architect-critic:critiquing-spec)`. No `target=`/`depth=`; both failure modes are silent.
- **Verification commands must assert a concrete observable** — a sha's reachability, a branch name, a file in a tree, a named string in output — **never rc alone.** Three P0s this series were git operations landing on the wrong branch with every rc check green.
