## Synthesis guidance

This file is the branch-loaded governance-pointer document. It is loaded when a
conversation touches planning, process, or doc management. Its purpose is a stable
pointer file — do NOT add project-specific prose beyond what is described below.

Governance docs: emit the canonical governance-docs list VERBATIM, preserving the
two-tier structure (standard `/scaffold-docs` set and `--full` extended set). The
list of doc names and their descriptions must match the template exactly. Do NOT
add project-specific doc entries — the template list is the complete canonical set.

If the project is not an LLM-project (i.e., `project_class` does not include
`llm-app` or `ai-agent`), note parenthetically that EVALS_PLAN, MODEL_CARD, and
PROMPT_GOVERNANCE are not generated for this project.

Workflow rules: emit the three canonical workflow rules VERBATIM from the template:
  1. MASTER-SPEC.md is canonical. Derived files are regenerated by `/scaffold-project`
     and `/scaffold-docs`.
  2. Hand-edits to derived files get overwritten on the next derive. Edit
     MASTER-SPEC.md instead.
  3. Live files (`05-active-context.md`, `06-progress.md`) are owned by slice work
     — never auto-rewritten.

Do NOT add project-specific workflow rules here. Custom rules belong in CLAUDE.md
or the project's MASTER-SPEC Phase 8/10. This document is intentionally static.
